Surface Grime

Two shaders are required for the surface grime. A fragment shader that organically dithers the grime when rendering, and a compute shader that updates the UV space map of the grime. Typically to update the pixels on a texture, you would deploy a compute shader that populates one thread per pixel. However, in order to find where a pixel is in 3D space, you need to know what triangle its on in UV space, and where that triangle is in 3D space. To accomplish this, I used the concepts behind multi shader render pipelines.

Like a conventional shader pipeline, a first pass is done to calculate position information for the pixels. This shader acts on each triangle, and calculates a 2x2 matrix to convert UV position to Bary Centric Coordinates. Additional information such as the bounds of the triangle UV position, and the vertex positions for the triangle are added to the same buffer.

A second shader pass acts on each triangle again, but with higher y and z group counts. Each thread then calculates its Bary centric position based on the triangle index (x), and the UV pixel offset (y, z). First the pixel checks if it is inside the triangle, and anti-aliases based on an array of sub sample points. Then, using the 3D vertex positions, each pixel's 3D position is found. This position can be used to calculate the distance from a check position, and update the grime map accordingly.

The material shader for the grime was initially a simple shader that multiplies the textures alpha by the grime maps alpha. This lead to nearly unnoticeable amounts of grime left, and didn't feel satisfying to clean. A basic sub pixel dithering would have fixed both, but felt very fake. Instead each screen pixel calculates a value based on a Worley Noise Map This map is calculated based on an RGB noise texture. 2 color channels are used to position a seed in each pixel, and the third channel is used to add randomness to the threshold value. Then, the alpha is set to 1 or 0 if the grime map is greater than or less than the Worley Noise Value. This system initially caused a severe performance hit, but because it looked better with a lower resolution grime map, that performance hit was made back elsewhere.
